# 11 - 部署模式与扩展

> OpenViking 支持多种部署模式，适应不同场景需求。

---

## 🎯 两种部署模式

### 1. 嵌入式模式

**适用场景：**
- 本地开发
- 单进程应用
- 个人使用
- 简单部署

```python
from openviking import SyncOpenViking

# 直接使用
client = SyncOpenViking(path="./data")
client.initialize()

# ... 使用 ...

client.close()
```

**特点：**
- ✅ 启动简单
- ✅ 无需额外服务
- ✅ 数据本地存储
- ❌ 不支持跨进程共享
- ❌ 单机部署

### 2. HTTP 服务模式

**适用场景：**
- 团队共享
- 生产环境
- 跨语言集成
- 多实例部署

#### 启动服务

```bash
# 启动 OpenViking 服务
python -m openviking serve --port 1933 --api-key your-key
```

#### 客户端连接

```python
from openviking import SyncHTTPClient

# 连接远程服务
client = SyncHTTPClient(
    url="http://localhost:1933",
    api_key="your-api-key"
)

# 使用方式与嵌入式相同
result = client.find("认证", target_uri="viking://resources/")
```

#### HTTP API 示例

```bash
# 搜索
curl http://localhost:1933/api/v1/search/find \
  -H "X-API-Key: xxx" \
  -d '{"query": "OAuth 认证", "target_uri": "viking://resources/"}'

# 添加资源
curl http://localhost:1933/api/v1/resources/add \
  -H "X-API-Key: xxx" \
  -F 'path=@./docs/api.md'
```

**特点：**
- ✅ 支持多客户端共享
- ✅ 跨语言支持（任何 HTTP 客户端）
- ✅ 适合团队协作
- ❌ 需要部署服务
- ❌ 网络延迟

## ⚡ 性能考量

### 影响性能的因素

| 因素 | 影响 | 优化建议 |
|------|------|----------|
| **向量搜索延迟** | 检索速度 | 使用本地/近端向量库 |
| **LLM 调用** | 摘要生成、意图分析 | 批量处理、缓存 |
| **AGFS 读写** | 文件操作 | 使用 SSD |
| **网络延迟**（HTTP 模式） | 客户端延迟 | 同机房部署 |

### 性能指标（参考）

| 操作 | 预期延迟 |
|------|----------|
| `add_resource`（小文件） | < 1s |
| `add_resource`（大文件） | 取决于文件大小 |
| `find`（简单查询） | < 100ms |
| `find`（复杂查询） | < 500ms |
| `commit`（会话提交） | < 2s |

### 垂直扩展

- 使用更大内存
- 使用 SSD 存储
- 使用更强的 GPU（如果有本地模型）
- 增加向量库缓存

## 🐛 常见问题

### Q: 内存占用太高

A: 考虑使用量化向量、使用本地 vLLM、减少缓存大小

### Q: 检索太慢

A: 检查向量库配置、使用更近的 API 端点、优化查询

### Q: 不想用云服务 API

A: 可以使用本地 vLLM + 本地向量数据库

### Q: 如何备份数据

A: 简单复制 `data` 目录即可（包含 AGFS 和向量库）
