    05 - 虚拟文件系统¶

    OpenViking 最大的创新：用"文件路径"来管理 Agent 的所有上下文。

    🎯 核心概念：Viking URI¶

    OpenViking 用 viking:// 协议定义了一套虚拟文件系统，每个上下文都有唯一标识。

    URI 格式¶

    viking://{scope}/{path}
    • scheme: 固定为 viking
    • scope: 顶级命名空间（resources、user、agent、session）
    • path: 作用域内的路径

    六大作用域¶

    作用域 说明 生命周期 用途
    resources 独立资源 长期 外部知识库
    user 用户数据 长期 用户偏好、记忆
    agent Agent 数据 长期 技能、指令、经验
    session 会话数据 会话内 当前对话记录
    queue 处理队列 临时 内部处理
    temp 临时文件 解析期间 内部临时

    📁 目录结构总览¶

    viking://
├── resources/                      # 独立资源（用户添加的知识）
│   └── {project-name}/
│       ├── .abstract.md            # L0: 项目一句话概述
│       ├── .overview.md            # L1: 项目结构导航
│       ├── README.md               # L2: 完整说明
│       ├── docs/                   # 文档目录
│       └── src/                    # 代码目录
│
├── user/                           # 用户相关数据
│   ├── .abstract.md               # L0: 用户数据概述
│   ├── .overview.md               # L1: 用户画像
│   └── memories/
│       ├── .overview.md           # 记忆总览
│       ├── profile.md             # 用户基本信息
│       ├── preferences/           # 按主题的偏好
│       │   ├── writing_style/
│       │   ├── code_style/
│       │   └── communication/
│       ├── entities/              # 实体记忆
│       │   ├── people/
│       │   └── projects/
│       └── events/                # 事件记录
│
├── agent/                          # Agent 相关数据
│   ├── .abstract.md               # L0: Agent 数据概述
│   ├── .overview.md               # L1: Agent 概览
│   ├── memories/                 # Agent 学习记忆
│   │   ├── cases/                # 问题解决方案
│   │   └── patterns/             # 可复用模式
│   ├── instructions/              # Agent 指令
│   └── skills/                   # 技能定义
│       ├── search-web/
│       └── code-execute/
│
└── session/
    └── {session_id}/              # 单个会话
        ├── .abstract.md           # L0: 会话概述
        ├── .overview.md           # L1: 会话内容
        ├── .meta.json             # 元数据
        ├── messages.jsonl         # 消息记录
        ├── history/               # 归档历史
        └── tools/                 # 工具调用

    🔍 URI 示例¶

    资源相关¶

    viking://resources/                           # 所有资源根目录
viking://resources/my-project/                # 具体项目
viking://resources/my-project/docs/           # 项目文档
viking://resources/my-project/docs/api.md    # 具体文件

    用户相关¶

    viking://user/                               # 用户根目录
viking://user/memories/                      # 所有用户记忆
viking://user/memories/preferences/          # 偏好目录
viking://user/memories/preferences/coding   # 编码偏好
viking://user/memories/entities/john_doe    # 某个实体

    Agent 相关¶

    viking://agent/                              # Agent 根目录
viking://agent/skills/                       # 所有技能
viking://agent/skills/search-web             # 具体技能
viking://agent/memories/cases/               # 案例记忆

    会话相关¶

    viking://session/{session_id}/                # 会话根目录
viking://session/{session_id}/messages/      # 消息记录
viking://session/{session_id}/history/       # 归档历史

    🛠️ 文件系统操作¶

    OpenViking 提供了类似本地文件系统的操作接口。

    列出目录¶

    entries = client.ls("viking://resources/")
# 返回:
# [
#   {"uri": "viking://resources/project-a/", "is_dir": True},
#   {"uri": "viking://resources/project-b/", "is_dir": True},
# ]

    读取文件¶

    content = client.read("viking://resources/docs/api.md")

    获取摘要（L0）¶

    abstract = client.abstract("viking://resources/docs/")
# 返回 ~100 tokens 的摘要

    获取概览（L1）¶

    overview = client.overview("viking://resources/docs/")
# 返回 ~2k tokens 的结构化概览

    模式匹配¶

    # 查找所有 md 文件
results = client.glob(pattern="**/*.md", uri="viking://resources/")

    搜索¶

    # 语义搜索
results = client.find("OAuth 认证", target_uri="viking://resources/")

    🏷️ 特殊文件¶

    每个目录都可能包含以下特殊文件：

    文件 用途 层级
    .abstract.md L0 摘要 L0
    .overview.md L1 概览 L1
    .relations.json 关联资源 -
    .meta.json 元数据 -

    relations.json 示例¶

    {
  "relations": [
    {
      "uri": "viking://resources/docs/security/",
      "reason": "安全相关的补充文档"
    },
    {
      "uri": "viking://resources/api-specs/",
      "reason": "包含完整的 API 定义"
    }
  ]
}

    🔄 为什么用文件系统范式？¶

    对比传统 RAG¶

    维度 传统 RAG OpenViking 文件系统
    组织方式 扁平向量库 层级目录结构
    定位方式 语义搜索 路径定位 + 语义搜索
    导航能力 无 可以"浏览"目录结构
    可观测性 黑盒 检索轨迹清晰
    人类可读 否 是（路径即语义）

    文件系统的优势¶

    ✅ 直观易懂
   用户可以直接"看到"信息的组织方式

✅ 可预测
   相同的路径总是指向相同的内容

✅ 便于调试
   检索过程可以可视化

✅ 符合直觉
   开发者都熟悉文件系统操作

    📝 最佳实践¶

    1. 使用尾部斜杠区分目录和文件¶

    # 目录
"viking://resources/docs/"

# 文件
"viking://resources/docs/api.md"

    2. 按作用域操作¶

    # 资源只添加到 resources 作用域
await client.add_resource(url, target="viking://resources/my-project/")

# 技能添加到 agent 作用域
await client.add_skill(skill_data)
# 自动到 viking://agent/skills/{skill-name}/

    3. 善用 L0/L1 做快速筛选¶

    # 先检查 L0/L1，确认相关后再加载 L2
async def get_context(uri, query):
    overview = await client.overview(uri)
    if not relevant(overview, query):
        return None

    # 确认相关，可以进一步搜索
    results = await client.find(query, target_uri=uri)
    return results

    🎯 API 参考¶

    URI 解析¶

    from openviking_cli.utils.uri import VikingURI

uri = VikingURI("viking://resources/docs/api")
print(uri.scope)        # "resources"
print(uri.full_path)    # "resources/docs/api"

# 父目录
parent = VikingURI(uri).parent.uri  # "viking://resources/docs"

    构建路径¶

    base = "viking://resources/docs/"
full = VikingURI(base).join("api.md").uri
# "viking://resources/docs/api.md"
