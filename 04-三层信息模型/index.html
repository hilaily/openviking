    04 - 三层信息模型（L0/L1/L2）¶

    "不要把所有信息一股脑塞给大模型，要学会分层管理。"

    🎯 为什么需要分层？¶

    想象一下图书馆的场景：

    ❌ 糟糕的做法:
用户问: "关于 Python 异步编程的书在哪？"
图书管理员: 把整个图书馆的书都搬给你 (Too Much Info)

✅ 好的做法:
1. 告诉你在哪个书架 (L0 摘要)
2. 告诉这个书架上有哪些相关书籍 (L1 概览)
3. 你确定要哪本后，再把书给你 (L2 详情)

    OpenViking 的 L0/L1/L2 三层模型就是这个思路。

    📊 三层概览¶

    层级 名称 Token 限制 用途 文件
    L0 摘要 ~100 快速筛选相关性 .abstract.md
    L1 概览 ~2k 理解结构导航 .overview.md
    L2 详情 无限制 完整内容 原始文件

    🔍 逐层详解¶

    L0: 摘要（Abstract）¶

    一句话总结，用于快速判断相关性。

    <!-- .abstract.md -->

API 认证指南，涵盖 OAuth 2.0、JWT 令牌和 API 密钥的安全访问方式。

    特点： - 超短（~100 tokens） - 机器可读，用于向量检索 - 快速过滤不相关内容

    使用场景：

    # 先用 L0 快速筛选
abstract = client.abstract("viking://resources/docs/auth")
if is_relevant(abstract):
    # 确实相关，再深入
    overview = client.overview("viking://resources/docs/auth")

    L1: 概览（Overview）¶

    结构化摘要，包含内容导航。

    <!-- .overview.md -->

# 认证指南概览

本指南涵盖 API 的三种认证方式：

## 章节
- **OAuth 2.0** (L2: oauth.md): 完整 OAuth 流程和代码示例
- **JWT 令牌** (L2: jwt.md): 令牌生成和验证
- **API 密钥** (L2: api-keys.md): 简单的密钥认证

## 要点
- OAuth 2.0 推荐用于面向用户的应用
- JWT 用于服务间通信

## 访问
使用 `read("viking://resources/docs/auth/oauth.md")` 获取完整文档。

    特点： - 适中长度（~2k tokens） - 包含导航信息（指向 L2 的路径） - 让 Agent 知道"在哪找详细内容"

    使用场景：

    # 构建 Agent 上下文时
overview = client.overview("viking://resources/docs/auth")
# L1 通常足够回答大多数问题

    🏗️ 目录结构示例¶

    每个目录都遵循统一结构：

    viking://resources/docs/auth/
├── .abstract.md          # L0: 一句话摘要
├── .overview.md          # L1: 结构化概览
├── .relations.json       # 关联资源

    嵌套目录¶

    viking://resources/my-project/
├── .abstract              # L0: 项目一句话概述
├── .overview              # L1: 项目整体介绍 + 导航

├── src/
│   ├── .abstract          # L0: src 目录概述
│   ├── .overview          # L1: src 目录说明

    🔄 生成机制¶

    何时生成？¶

    场景 生成器
    添加资源时 SemanticProcessor
    会话归档时 SessionCompressor

    生成顺序（自底向上）¶

    叶子节点 → 父目录 → 根目录

    子目录的 L0 会被聚合成父目录的 L1。

    例如:
├── src/utils/helpers.py 的 L0
└── src/utils/ 的 L1 包含 src/utils/helpers.py 的摘要
    └── src/ 的 L1 包含 src/utils/ 的摘要
        └── 项目根的 L1 包含 src/ 的摘要

    L0/L1 聚合过程¶

    # 伪代码
def generate_abstract(uri):
    # 如果是文件，直接生成 L0
    if is_file(uri):
        return llm.extract_abstract(content)

    # 如果是目录，聚合子节点的 L0
    children = list_children(uri)
    child_abstracts = [generate_abstract(child) for child in children]
    return llm.summarize(child_abstracts)

    🎯 使用策略¶

    给 LLM 构建上下文¶

    # 通常 L1 就足够了
def build_context(query, target_uri):
    overview = client.overview(target_uri)

    # 检查 L1 是否包含答案
    if can_answer_in(overview, query):
        return overview

    # 否则加载 L2
    return client.read(target_uri)

    Token 预算管理¶

    # 示例：根据上下文大小动态调整
BUDGET_TOKENS = 8000

def get_context(target_uri, budget=BUDGET_TOKENS):
    # 先获取 L1
    overview = client.overview(target_uri)

    if len(overview) < budget:
        return overview

    # L1 太大，只用 L0
    return client.abstract(target_uri)

    🎓 最佳实践¶

    场景 推荐层级 原因
    快速相关性检查 L0 100 tokens，快速判断
    理解内容范围 L1 包含导航信息
    详细信息提取 L2 完整内容
    给 LLM 构建上下文 L1 通常足够，成本可控

    不要做的事¶

    # ❌ 错误：每次都加载完整内容
content = client.read("viking://resources/big-project/")  # 可能是几 MB

# ✅ 正确：先检查 L0/L1
overview = client.overview("viking://resources/big-project/")
if not related: return

content = client.read("viking://resources/big-project/specific-file.md")
