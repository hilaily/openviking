# 08 - 检索机制详解

> OpenViking 的检索不是简单的向量匹配，而是"意图分析 + 目录递归 + 重排序"的精细化过程。

---

## 🎯 概览：两阶段检索

```
┌─────────────────────────────────────────────────────────────────┐
│                        检索流程                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   查询输入                                                       │
│       │                                                         │
│       ▼                                                         │
│  ┌──────────────────┐                                           │
│  │   意图分析        │  →  理解用户真实需求                       │
│  │ IntentAnalyzer   │     生成 0-5 个结构化查询                  │
│  └────────┬─────────┘                                           │
│           │                                                     │
│           ▼                                                     │
│  ┌──────────────────┐    ┌──────────────────┐                 │
│  │   层级检索        │ ←→ │   Rerank 精排     │                 │
│  │HierarchicalSearch│    │                  │                 │
│  └────────┬─────────┘    └──────────────────┘                 │
│           │                                                     │
│           ▼                                                     │
│  ┌──────────────────┐                                           │
│  │    返回结果      │  →  按相关性排序的上下文                    │
│  │  MatchedContext  │                                           │
│  └──────────────────┘                                           │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 🆚 find() vs search()

| 特性 | `find()` | `search()` |
|------|----------|------------|
| **会话上下文** | 不需要 | 需要 |
| **意图分析** | ❌ 不使用 | ✅ 使用 LLM 分析 |
| **查询数量** | 单一查询 | 0-5 个 TypedQuery |
| **延迟** | 低 | 较高（多一次 LLM 调用） |
| **适用场景** | 简单查询 | 复杂任务 |

### 使用场景

```python
# find(): 简单查询，不需要会话上下文
results = client.find(
    "OAuth 认证",
    target_uri="viking://resources/"
)

# search(): 复杂任务，需要理解对话历史
results = client.search(
    "帮我创建一个 RFC 文档",
    session_info=session  # 需要会话上下文
)
```

## 🔍 第一阶段：意图分析

**IntentAnalyzer** 使用 LLM 分析查询意图，生成结构化查询。

### 输入

- 会话压缩摘要
- 最近 5 条消息
- 当前查询

### 输出：TypedQuery

```python
@dataclass
class TypedQuery:
    query: str           # 重写后的查询文本
    context_type: ContextType  # MEMORY / RESOURCE / SKILL
    intent: str          # 查询目的
    priority: int        # 1-5 优先级
```

### 查询风格规范

| context_type | 风格 | 示例 |
|--------------|------|------|
| **SKILL** | 动词开头 | "创建 RFC 文档"、"提取 PDF 表格" |
| **RESOURCE** | 名词短语 | "RFC 文档模板"、"API 使用指南" |
| **MEMORY** | "用户XX" | "用户的代码规范偏好" |

### 示例

```
用户输入: "帮我查一下 OAuth 认证流程，然后写个示例代码"

意图分析后可能生成:

[
    {
        "query": "OAuth 认证流程说明",
        "context_type": "RESOURCE",
        "intent": "获取认证流程文档",
        "priority": 1
    },
    {
        "query": "网络搜索",
        "context_type": "SKILL",
        "intent": "查找最新 OAuth 实现",
        "priority": 2
    },
    {
        "query": "用户的代码风格偏好",
        "context_type": "MEMORY",
        "intent": "了解用户偏好的代码风格",
        "priority": 3
    }
]
```

### 特殊情况

- **0 个查询**: 闲聊、问候等不需要检索的场景
- **多个查询**: 复杂任务可能需要同时使用技能 + 资源 + 记忆

## 📂 第二阶段：层级检索

**HierarchicalRetriever** 使用优先队列递归搜索目录结构。

### 核心思想

```
不是盲目搜索，而是：
1. 先定位最相关的"目录"（高层语义）
2. 在目录内递归搜索
3. 理解信息的上下文关系
```

### 检索流程

```
Step 1: 根据 context_type 确定根目录
        ↓
Step 2: 全局向量搜索定位起始目录
        ↓
Step 3: 合并起始点 + Rerank 评分
        ↓
Step 4: 递归搜索子目录（使用优先队列）
        ↓
Step 5: 收敛检测，收集结果
```

### 根目录映射

| context_type | 根目录 |
|--------------|--------|
| MEMORY | `viking://user/memories`, `viking://agent/memories` |
| RESOURCE | `viking://resources` |
| SKILL | `viking://agent/skills` |

### 递归搜索算法

```python
def hierarchical_search(query, root_uri):
    # Step 2: 全局搜索定位起始目录
    candidates = vector_search(query, top_k=3)
    
    # 优先队列: (score, uri)
    dir_queue = [(c.score, c.uri) for c in candidates]
    collected = []
    
    while dir_queue:
        # 取出最高分的目录
        current_score, current_uri = heapq.heappop(dir_queue)
        
        # 在当前目录搜索子节点
        child_results = search_children(current_uri, query)
        
        for r in child_results:
            # 分数传播: 50% 自己 + 50% 父目录
            final_score = 0.5 * r.embedding_score + 0.5 * current_score
            
            if final_score > threshold:
                collected.append(r)
                
                # 如果是目录，继续递归
                if not r.is_leaf:
                    heapq.heappush(dir_queue, (final_score, r.uri))
        
        # 收敛检测：连续 3 轮 top-k 不变则停止
        if topk_unchanged_for_3_rounds:
            break
    
    return collected
```

### 关键参数

| 参数 | 值 | 说明 |
|------|-----|------|
| `SCORE_PROPAGATION_ALPHA` | 0.5 | 50% embedding + 50% parent |
| `MAX_CONVERGENCE_ROUNDS` | 3 | 收敛检测轮数 |
| `GLOBAL_SEARCH_TOPK` | 3 | 全局搜索候选数 |
| `MAX_RELATIONS` | 5 | 每资源最大关联数 |

## 🎯 第三阶段：Rerank 精排

**Reranker** 在 THINKING 模式下对候选结果进行精排。

### 触发条件

- 配置了 Rerank API（AK/SK）
- 使用 THINKING 模式（`search()` 默认）

### 评分方式

```python
if rerank_client and mode == THINKING:
    # 使用重排序模型
    scores = rerank_client.rerank_batch(query, documents)
else:
    # 使用向量相似度分数
    scores = [r["_score"] for r in results]
```

### 使用位置

1. **起始点评估**: 评估全局搜索的候选目录
2. **递归搜索**: 评估每层的子节点

### 支持的后端

| 后端 | 模型 |
|------|------|
| Volcengine | `doubao-seed-rerank` |

## 📊 检索结果

### MatchedContext

```python
@dataclass
class MatchedContext:
    uri: str                # 资源 URI
    context_type: ContextType
    is_leaf: bool           # 是否文件
    abstract: str           # L0 摘要
    score: float            # 最终分数
    relations: List[RelatedContext]  # 关联上下文
```

### FindResult

```python
@dataclass
class FindResult:
    memories: List[MatchedContext]   # 记忆结果
    resources: List[MatchedContext] # 资源结果
    skills: List[MatchedContext]    # 技能结果
    query_plan: Optional[QueryPlan]  # search() 时的查询计划
    query_results: Optional[List[QueryResult]]
    total: int                      # 总数
```

### 使用示例

```python
results = client.find("Python 异步编程", target_uri="viking://resources/")

# 遍历结果
for ctx in results.resources:
    print(f"\nURI: {ctx.uri}")
    print(f"相关度: {ctx.score:.4f}")
    print(f"摘要: {ctx.abstract}")
    
    # 读取完整内容
    if needs_detail:
        content = client.read(ctx.uri)
```

## 📈 与传统 RAG 对比

| 维度 | 传统 RAG | OpenViking 检索 |
|------|----------|----------------|
| **检索单元** | 文本片段 | 目录 + 文件 |
| **检索策略** | 单一向量匹配 | 目录递归检索 |
| **上下文理解** | 无 | 目录层级结构 |
| **结果排序** | 单一分数 | 多阶段精排 |
| **可观测性** | 黑盒 | 检索轨迹可视化 |
