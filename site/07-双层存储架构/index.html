    07 - 双层存储架构¶

    OpenViking 采用"内容 + 索引"分离的双层存储设计，让存储和检索各司其职。

    🎯 为什么需要双层存储？¶

    单一存储方案的问题：

    方案 问题
    纯向量库 无法存储完整内容，检索后需要回查
    纯文件存储 语义检索能力弱
    混合存储 通常是简单拼接，缺乏统一抽象

    OpenViking 的答案¶

    内容存储 (AGFS) + 向量索引 = 双层存储

    分工明确： - AGFS 负责存"内容"（L0/L1/L2、文件、媒体） - 向量库 负责"检索"（URI 映射、语义向量）

    🏗️ 架构图¶

    ┌─────────────────────────────────────────┐
│            VikingFS (URI 抽象层)         │
│    URI 映射 · 层级访问 · 关联管理        │
│        提供统一操作接口，屏蔽底层细节      │
└────────────────┬────────────────────────┘
                 │
        ┌────────┴────────┐
        │                 │
┌───────▼────────┐  ┌─────▼───────────┐
│      AGFS       │  │    向量数据库    │
│    (内容存储)    │  │    (语义索引)   │
│                 │  │                 │
│ - L0/L1/L2 文件 │  │ - URI 映射      │
│ - 多媒体内容    │  │ - 语义向量      │
│ - 关联关系      │  │ - 元数据        │
│                 │  │ - 使用计数      │
└─────────────────┘  └─────────────────┘

    📦 第一层：AGFS¶

    AGFS (Abstracted Granular File System) 是 OpenViking 的内容存储层。

    设计目标¶

    • 统一的文件操作接口
    • 支持多种后端（本地、S3 等）
    • 原生支持 L0/L1/L2 三层结构
    • 管理资源间的关联关系

    目录结构¶

    ./data/agfs/
└── viking/
    ├── resources/
    │   └── my-project/
    │       ├── .abstract.md          # L0
    │       ├── .overview.md          # L1
    │       ├── README.md             # L2
    │       └── src/
    │           └── main.py
    │
    ├── user/
    │   └── memories/
    │       ├── profile.md
    │       └── preferences/
    │           └── coding_style.md
    │
    └── agent/
        ├── skills/
        │   └── search-web/
        │       ├── .abstract.md
        │       └── SKILL.md
        └── memories/
            └── patterns/

    后端支持¶

    后端 说明 配置项
    localfs 本地文件系统 path
    s3fs S3 兼容存储 bucket, endpoint
    memory 内存存储（测试） -

    核心 API¶

    # 读取
content = agfs.read(uri)              # 读取文件
abstract = agfs.abstract(uri)         # 读取 L0
overview = agfs.overview(uri)          # 读取 L1

# 写入
agfs.write(uri, content)              # 写入文件
agfs.mkdir(uri)                       # 创建目录

# 管理
agfs.rm(uri, recursive=True)          # 删除（自动清理向量）
agfs.mv(old_uri, new_uri)             # 移动（自动更新向量 URI）
agfs.link(from_uri, to_uri)           # 创建关联

# 查询
entries = agfs.ls(uri)                # 列出目录
relations = agfs.relations(uri)        # 获取关联

    关联管理¶

    AGFS 通过 .relations.json 管理资源间的关联：

    {
  "relations": [
    {
      "uri": "viking://resources/docs/security/",
      "reason": "安全相关的补充文档"
    },
    {
      "uri": "viking://resources/api-specs/",
      "reason": "API 规范定义"
    }
  ]
}

    🔍 第二层：向量数据库¶

    向量数据库存储语义索引，支持快速检索。

    存储内容¶

    字段 类型 说明
    id string 主键
    uri string 资源 URI
    parent_uri string 父目录 URI
    context_type string resource/memory/skill
    is_leaf bool 是否叶子节点
    vector vector 密集向量
    sparse_vector sparse_vector 稀疏向量
    abstract string L0 摘要文本
    name string 名称
    description string 描述
    created_at string 创建时间
    active_count int64 使用次数

    索引策略¶

    index_meta = {
    "IndexType": "flat_hybrid",  # 混合索引
    "Distance": "cosine",        # 余弦距离
    "Quant": "int8",             # int8 量化
}

    后端支持¶

    后端 说明
    local 本地持久化向量库
    http HTTP 远程向量服务
    volcengine 火山引擎 VikingDB

    向量搜索示例¶

    # 基础搜索
results = vector_db.search(
    query_vector=[0.1, 0.2, ...],
    top_k=10
)

# 带过滤的搜索
results = vector_db.search(
    query_vector=[0.1, 0.2, ...],
    filter={"context_type": "resource"},
    top_k=10
)

    🔄 同步机制¶

    VikingFS 自动维护 AGFS 和向量库的一致性。

    删除同步¶

    # 删除目录时，自动清理向量库
viking_fs.rm("viking://resources/docs/auth", recursive=True)
# 向量库中所有以此 URI 开头的记录都会被删除

    移动同步¶

    # 移动目录时，自动更新向量库中的 URI
viking_fs.mv(
    "viking://resources/docs/auth",
    "viking://resources/docs/authentication"
)
# 向量库中的 uri 和 parent_uri 字段都会更新

    📊 优势对比¶

    设计优势¶

    优势 说明
    职责清晰 向量库只负责检索，AGFS 负责存储
    内存优化 向量库不存文件内容，节省内存
    单一数据源 所有内容从 AGFS 读取，向量库只存引用
    独立扩展 向量库和 AGFS 可分别扩展

    实际收益¶

    ✅ 向量库更小更快（只存索引，不存内容）
✅ AGFS 可以用任何存储后端（S3、本地、云存储）
✅ 检索结果直接从 AGFS 读取，无需回查
✅ 统一 URI 抽象，底层存储透明

    💻 代码示例¶

    完整流程¶

    import openviking as ov

client = ov.SyncOpenViking(path="./data")
client.initialize()

# 1. 添加资源（写入 AGFS + 建立向量索引）
result = client.add_resource(
    path="./docs/api.md",
    target="viking://resources/my-api/"
)
print(f"添加成功: {result['root_uri']}")

# 2. 等待语义处理完成
client.wait_processed()

# 3. 检索（从向量库搜索，从 AGFS 读取）
results = client.find(
    "认证方式",
    target_uri="viking://resources/my-api/"
)

for r in results.resources:
    # 从 AGFS 读取内容
    content = client.read(r.uri)
    print(f"\n{r.uri}:\n{content[:200]}...")

# 4. 删除（同步清理 AGFS 和向量库）
client.rm("viking://resources/my-api/")

client.close()
