    01 - OpenViking 是什么？¶

    "AI Agent 的记忆系统，本质上是一个精心设计的信息管理系统。"

    🎯 一句话定义¶

    OpenViking 是字节跳动火山引擎 Viking 团队开源的上下文数据库（Context Database），专门为 AI Agent 设计，用于统一管理记忆、知识资源和技能。

    🤔 它解决什么问题？¶

    在 AI Agent 开发中，上下文管理是一个核心难题：

    ❌ 传统方案的痛点¶

    问题 表现
    碎片化 记忆在代码里，资源在向量库，技能散落各处
    检索不准 传统 RAG 是扁平的，缺乏全局视野
    不可观测 检索过程是黑盒，出错时无法调试
    记忆难迭代 只能记录对话，缺乏任务记忆
    Token 浪费 不分层，一股脑塞进 prompt

    ✅ OpenViking 的答案¶

    用「文件系统范式」重新定义上下文管理

    把 Agent 需要的所有信息（记忆、资源、技能）统一抽象为一个虚拟文件系统，让开发者像管理本地文件一样管理 Agent 的"大脑"。

    💡 核心设计理念¶

    1. 文件系统范式¶

    传统 RAG:  扁平文本切片 → 向量相似度匹配
OpenViking: 虚拟文件系统 → 目录路径定位 + 语义检索

    Agent 不再只能靠"猜"来找信息，而是可以： - ✅ 用 ls 列出目录结构 - ✅ 用 read 读取文件内容 - ✅ 用 find 搜索相关信息 - ✅ 追踪信息的来源路径

    2. 三层信息模型 (L0/L1/L2)¶

    按需加载，避免信息过载：

    层级 名称 大小 用途
    L0 摘要 ~100 tokens 快速判断相关性
    L1 概览 ~2k tokens 理解内容导航
    L2 详情 无限制 按需获取完整内容

    3. 目录递归检索¶

    不是简单地匹配向量，而是： 1. 先定位最相关的目录 2. 在目录内递归搜索 3. 理解信息的上下文关系 4. 返回更精准的结果

    4. 自动记忆进化¶

    Agent 与用户交互后，会自动： - 压缩历史消息 - 提取长期记忆 - 更新用户偏好 - 积累使用经验

    越用越聪明。

    🔄 与传统方案对比¶

    维度 传统 RAG OpenViking
    存储方式 扁意向量库 虚拟文件系统 + 向量索引
    检索方式 单一向量匹配 目录递归检索
    信息分层 无 L0/L1/L2 三层
    记忆迭代 无 自动提取
    可观测性 黑盒 检索轨迹可视化
    上下文类型 只有文档 资源+记忆+技能统一

    📦 核心模块¶

    模块 职责
    Client 统一入口，SDK/API 接口
    Service Layer 业务逻辑（FS、Search、Session、Resource 等服务）
    Retrieve 意图分析 + 层级检索 + Rerank
    Session 会话管理、记忆提取
    Parse 文档解析、树构建
    Storage AGFS + 向量库双层存储

    🎯 适用场景¶

    ✅ 适合使用 OpenViking 的场景¶

    • 需要长期记忆的 AI Agent
    • 大量外部知识需要管理
    • 复杂任务需要多轮对话
    • 想要 Agent 越用越聪明
    • 需要可观测的检索过程

    ❌ 可能不需要的场景¶

    • 简单问答机器人
    • 一次性使用的脚本
    • 预算极其有限（需要 API 成本）
    • 已有成熟的记忆方案

    🐂 团队背景¶

    OpenViking 由字节跳动火山引擎 Viking 团队开源。

    该团队在向量数据库和上下文工程领域有深厚积累：

    • 2019: VikingDB 向量数据库支持字节全业务
    • 2023: VikingDB 登录火山引擎公有云
    • 2024: 发布开发者产品矩阵
    • 2025: 开源 MineContext
    • 2026: 开源 OpenViking
